# Scripts

The generated Lean files (header `-- Generated by …; do not edit.`) are produced by the programs
below, most of them using the [computational supplement](../../python/README.md) to
[Scott Duke Kominers’s manuscript](../../README.md). The generators need not be trusted: every
generated datum is checked by the Lean kernel, and only decides whether a check succeeds. From the
committed inputs and the supplement, each Python generator reproduces the committed Lean files
byte for byte.

Start in the repository root and set the supplement path for the commands below.

```sh
cd lean
ARCHIVE=../python
```

The Python programs need Python 3.10 or later and only the standard library.

## The local tables (`tables/`)

| Step | Command | Output |
| --- | --- | --- |
| 1 | `gcc -O2 -o witdp scripts/tables/witdp.c` | the dynamic program for the local representation tables in Appendix A.1 |
| 2 | `python3 -I scripts/tables/gen_tables.py ./witdp` | `KimKimOh/Tables/Data/T{32,92,33,93}.lean`: the tables `ℛ_{j,p}` with one witness per orbit |
| 3 | `python3 -I scripts/tables/gen_checks.py` | `KimKimOh/Tables/Check*.lean`: their kernel checks |
| 4 | `python3 -I scripts/tables/gen_profiles.py "$ARCHIVE"` | `KimKimOh/Tables/Data/ProfileData.lean`: the profiles in Appendix A.2 |
| 5 | `python3 -I scripts/tables/gen_chunkdata.py "$ARCHIVE"` | `KimKimOh/Tables/Data/ChunkData.lean`: the profile masks and worst-step tables of each chunk |
| 6 | `python3 -I scripts/tables/gen_profchecks.py` | `KimKimOh/Tables/ProfCheck*.lean`, `KimKimOh/Tables/ProfChecks.lean`: their kernel checks |

`witdp -a` prints the accepted residues; `gen_tables.py` cross-checks them at 2 with a dynamic
program in Python. The counts agree with Table 3 of the manuscript.

## The first pass (`firstpass/`)

These steps evaluate the Lean definitions themselves, so they need the light modules built
(`lake build KimKimOh.Enum`).

| Step | Command | Output |
| --- | --- | --- |
| 1 | `lake env lean --run scripts/firstpass/Heavy.lean 3` (and `9`) | `scripts/firstpass/data/heavy{3,9}.txt`: the pairs `(a, t)` to enumerate, with their cost; prints `amaxT` |
| 2 | `lake env lean --run scripts/firstpass/RegionEval.lean 3` (and `9`) | `scripts/firstpass/data/left{3,9}.txt`: the blocks of the region that fail the whole-block test |
| 3 | `python3 -I scripts/firstpass/gen_enum.py` | `KimKimOh/FirstPassChecks/`: the lists, the `enumOK` and dispatcher checks, and their assembly |

Both programs take the determinant of `K`, 3 or 9. The outputs of steps 1 and 2 are committed in
`scripts/firstpass/data/`. Certificate 4.2 gives 536 and 1,136 pairs, and Certificate 4.3(a)
gives 836 and 5,147 remaining blocks, for $L_6$ and $L_9$, respectively.

## The last-column test (`terminal/`)

| Step | Command | Output |
| --- | --- | --- |
| 1 | `python3 -I scripts/terminal/gen_terminal.py "$ARCHIVE"` | `KimKimOh/Tables/Data/TermTables.lean`, `KimKimOh/Terminal/`: the tables of the last-column test, and a certificate (`TermCert`) and check for every block left by the first pass |

It reads the blocks from `KimKimOh/FirstPassChecks/Data{3,9}.lean`, and the records
`audit/coverage.json.gz` and `audit/witnesses.jsonl.gz` from the supplement through the
supplement's checker. These records are identical to `certificates/last_column_bounds.json.gz`
and `certificates/representation_witnesses.jsonl.gz`, respectively. The generator stops if a
witness key occurs twice or a witness is unused. Its docstring describes the certificate format.

## Local witnesses for the genera (`genus/`)

These do not read the supplement.

| Command | Output |
| --- | --- |
| `python3 -I scripts/genus/gen_local_binary.py > KimKimOh/Local/BinaryData.lean` | witnesses for the local 2-universality of `K₉` |
| `python3 -I scripts/genus/gen_kko112.py data > KimKimOh/Genus/Kko112Data.lean` | local witnesses and transfer matrices for `⟨1, 1, 2⟩ ⊥ A₂` |
| `python3 -I scripts/genus/gen_kko112.py hard > KimKimOh/Genus/Kko112HardData.lean` | witnesses for its doubly hard binaries |

## Lean scripts

- `CheckAxioms.lean`, `CheckAxiomsMain.lean`: fail unless the listed theorems depend only on
  `propext`, `Classical.choice` and `Quot.sound`. CI runs the first; the second needs the kernel
  checks.
- `ci_modules.py`: the modules CI builds (those not depending on a generated kernel check).
- `full_build.py`: the parts of the full verification ([GitHub workflow](../../.github/workflows/full.yml)): the light
  modules, and the heavy modules in four parts of about equal cost in dependency order, from the
  available build times in `module_costs.json` (60 seconds per module without a timing).
  On the release tree, `python3 scripts/full_build.py check` compares the parts with every
  first-party source file, including `KimKimOh.lean`.
- `ReplayModule.lean`: replays one compiled module by exact name in the environment of its
  imports, using Lean's kernel. The replay jobs run it once per assigned module.
- `test_exact_replay.sh`: checks that a parent module still replays when a descendant's import
  is missing, and that replay fails for the descendant and for an absent module.
